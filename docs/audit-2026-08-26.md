## Phase E — Plugins + Bundle Optimization (Completed 2026-08-26)

### E1: NoteView lazy-loaded — 512KB removed from initial load
- **Problem:** NoteView was the only eagerly-imported view, dragging the entire 512KB tiptap vendor chunk into the initial bundle.
- **Fix:** Converted to `React.lazy()` like all other views.
- **Result:** `index.js` dropped from **86KB → 71.6KB** (-17%).
- **File:** `src/components/layout/MainArea.tsx`

### E2: Tiered chunk splitting for vendor-tiptap
- **Problem:** Single 512KB `vendor-tiptap` chunk loaded everything at once.
- **Fix:** Split into 4 tiers in `vite.config.ts`:
  - `vendor-prosemirror` (251KB) — core, loaded with editor
  - `vendor-tiptap` (189KB) — extensions, loaded with editor
  - `vendor-tiptap-markdown` (60KB) — loaded on demand
  - `vendor-tiptap-tables` (12KB) — loaded on demand
- **Result:** Initial load reduced from ~512KB tiptap to ~440KB (prosemirror + tiptap core). Markdown and tables load separately.
- **File:** `vite.config.ts`

### E3: Plugin sandbox hardening
- **Log buffer capped:** FIFO buffer with max 5,000 entries (was unbounded). Prevents OOM from log-flood attacks.
- **Force terminate:** Added `terminate()` action to `pluginStore` + "Force stop" button (■) in `PluginsView` UI. Users can now kill stuck/infinite-loop plugins.
- **Files:** `src/core/plugins/host.ts`, `src/stores/pluginStore.ts`, `src/components/plugins/PluginsView.tsx`

### E4: Test updated
- Updated `host.test.ts` log flood test to expect capped buffer (5000) instead of unbounded (100K).

### H3a — Plugin Keybinding API

**Goal:** let plugins register custom keyboard shortcuts from inside the sandboxed worker, wired into the existing command + shortcut system.

**Design**
- New pure module `src/core/plugins/keybindingRegistry.ts` — a plugin-scoped bindings registry. Each binding = `{ plugin, id, commandId, spec: ShortcutSpec {key, mod?, shift?, alt?} }`. Booleans normalized to `false` for predictable specs. Ops: `register`, `unregister`, `clearPlugin`, `clearAll`, `all`, and `match(e, isMac)` → first binding whose chord matches (first-match-wins keeps plugins isolated). Reuses `matchesShortcut` from `src/core/shortcuts/model`.
- **Worker (`public/plugin-worker.js`)**: added `nx.registerKeybinding(spec, commandId)` → posts `{ type: 'register-keybinding', spec, commandId }`.
- **Host (`host.ts`)**: new `register-keybinding` message case — maps the plugin's (relative) commandId to the full host id `plugin:<plugin>:<commandId>` (matching the command it registered) and calls `pluginKeybindings.register`. Keybindings are torn down with the plugin (`clearPlugin` in `terminatePlugin` and `unloadAll`) so an unloaded/disabled plugin can't leave stray chords.
- **Dispatch (`App.tsx`)**: a dedicated `keydown` listener checks `pluginKeybindings.match(e, isMac)` and runs the bound command via `commands.run`. It is installed after the built-in shortcut listeners and bails when `e.defaultPrevented`, so built-in shortcuts always win and there are no double-fires. `?`-help keeps typing safe since chords use `Mod`.

**Tests**
- `keybindingRegistry.test.ts` — 7 tests: empty start, per-plugin keying, chord match (Ctrl on non-Mac / Meta on Mac), first-match-wins ambiguity, unregister, clearPlugin isolation, clearAll.
- `host.test.ts` — `nx.registerKeybinding` end-to-end through a real worker: registers `plugin:testplug:jump` with the correct normalized spec.

**Design consistency**
- Reuses `ShortcutSpec`/`matchesShortcut`, the existing `commands` registry, and the sandbox message-passing pattern — no new global mechanism. Plugin keybindings surface no host globals (stays inside the worker bridge).
